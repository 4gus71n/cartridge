Host your game on GitHub Pages + Releases

Cartridge doesn't host your files. You give us two links, and both can be free on GitHub:

  • Play URL: where the game runs in a browser (GitHub Pages).
  • Package URL: a .zip of the same build that the app downloads so people can play offline (a GitHub Release asset).

When we approve a version we pin the zip's SHA-256 checksum. If the file behind the URL changes later, the app refuses it and keeps the approved copy. To ship changes, publish a new release and press Submit update in the portal.

1. Prepare the build

  • index.html must be at the root of the build (or inside one top-level folder of the zip, which we flatten).
  • Add a LICENSE file (or COPYING) at the root. Allowed licenses: MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, MPL-2.0, Unlicense, CC0-1.0, CC-BY-4.0. GPL-family, CC-BY-SA, non-commercial and unlicensed games can't be accepted. The license you pick in the form must match the file.
  • Use only relative paths (./game.js, assets/hero.png), no absolute /... paths, no symlinks.
  • Limits: zip up to 50 MB, up to 100 MB unpacked, up to 5,000 files.

2. Make it work offline

Players often open games on the subway. Our checks load your game in a phone-sized headless browser with the internet turned off.

  • Bundle every library, font and asset in the zip. Don't load scripts from CDNs (jsDelivr, unpkg, cdnjs, Google Fonts…). Copy them into your project instead.
  • No analytics, trackers, ads or remote calls. Store saves in localStorage.
  • Uncaught JavaScript errors while booting fail the checks.

3. Make it phone-friendly

  • Add <meta name="viewport" content="width=device-width, initial-scale=1">.
  • Everything must be playable with touch. No keyboard or mouse should be required. Use pointer or touch events and on-screen buttons.
  • Scale to the screen (we test at 412×915). Pick portrait or landscape in the form.
  • Start fast: show something within a few seconds and avoid huge initial downloads.

4. Publish the Play URL on GitHub Pages

  1. Push your build to a public GitHub repository (for example you/my-game).
  2. Open Settings → Pages, choose Deploy from a branch, pick main and the folder that has index.html (/ or /docs).
  3. After a minute the game is live at https://you.github.io/my-game/. That's your Play URL.

5. Attach the zip to a GitHub Release (Package URL)

cd my-game-build          # the folder with index.html and LICENSE
zip -r ../my-game-v1.zip . -x '.*'
gh release create v1 ../my-game-v1.zip --title "v1" --notes "First Cartridge build"

Or use the website: Releases → Draft a new release, add a tag such as v1, drop the zip into Attach binaries and publish. Right-click the asset to copy its link. It looks like this:

https://github.com/you/my-game/releases/download/v1/my-game-v1.zip

That's your Package URL. For updates, create v2 with a new zip and submit the new link.

6. Submit and wait for review

  1. Log in at /portal, accept the creator terms and press New game.
  2. Automated checks run in a minute or two: download, zip safety, license, external hosts, an offline boot at phone size with a screenshot, and whether the play URL is reachable. You'll see each result in My games.
  3. If something fails, fix it, publish a new release and submit an update. If everything passes, a person reviews the game. Approved games show up in the Cartridge feed.
